# Saros 部署说明（前后端拆分 + Docker）

> 适用：把 Saros 部署到 Linux 服务器（PG 所在的那台机器）。前端 + 后端进 Docker，
> PG 留在宿主机不动。Mac 上 `./dev.sh` 的本地开发方式不受影响。
> 方案设计见 [docs/部署方案.md](部署方案.md)。

## 一、部署架构

```
浏览器 ── 80 端口 ──> nginx 容器（前端静态文件 + 反代 /api）
                          │
                          └──> backend 容器（FastAPI :8000，单实例）
                                 │
                                 ├── 经宿主机 Tailscale ──> PG（宿主机，未容器化）
                                 ├── 经宿主机 Tailscale ──> ASR（另一台机器）
                                 └── 挂载 /app/data <── 宿主 backend/data（媒体/模型/cookie）
```

- 前端容器与 PG 是阶段三的复用资产：阶段三 Java 后端上线时**前端容器零改动**（只改 nginx 反代目标），PG 与 backend/data 继续共用。
- 容器出站流量经宿主机 NAT，PG/ASR 看到的来源 IP 是**宿主机自身的 Tailscale IP**（唯一例外：目标是宿主机自己 IP 时，见「常见问题」）。

## 二、前置条件

1. 服务器已装 Docker Engine + compose 插件 v2（`docker compose version` 可用）。
2. 服务器已装 Tailscale，与 PG（同机）和 ASR 机器（100.100.61.45）互通。
3. 代码仓库可达：`git clone https://github.com/Yq135/Saros-python.git`（已有仓库则直接 git pull）。
4. 80 端口空闲（旧前端服务先停）。

## 三、首次部署

1. **拉代码**：`git clone https://github.com/Yq135/Saros-python.git && cd Saros-python`（已有仓库则 `git pull`）。

2. **放置 backend/.env**（被 gitignore，不会随 git 到达服务器；compose 把它挂载进容器，**必须先于首次 up 存在**，否则 Docker 会在该路径建一个目录）：
   - 从 Mac 拷贝：`scp backend/.env 服务器:~/Saros-python/backend/.env`；
   - 或服务器上手工创建：`cp backend/.env.example backend/.env` 后按实际填写；
   - 现网值可直接沿用：PG_HOST 是服务器自身 Tailscale IP 无需改；EMBEDDING_MODEL / COOKIE_PATH 相对路径在容器内（/app 下）同样成立；
   - 值中含 `#` 等特殊字符的键用双引号包裹，如 `PG_PASSWORD="saros#2026!"`。

3. **同步 backend/data**（约 432MB：媒体 + cookie + bge-small-zh-v1.5 模型；gitignore）：
   ```bash
   rsync -avz --progress backend/data/ 服务器:~/Saros-python/backend/data/
   ```
   服务器上若本来就有运行环境的 backend/data，直接 `cp -r` 到仓库对应位置即可。

4. **PG 放行容器网段**（唯一一次 PG 侧配置，一行 + reload，不是迁移）：
   容器访问宿主机自身 IP 时源地址是容器网段 IP，pg_hba.conf 需加一行（加密方式与文件内现有行保持一致，scram-sha-256 或 md5）：
   ```
   host    saros_db    saros    172.28.0.0/24    scram-sha-256
   ```
   然后 `sudo -u postgres psql -c "SELECT pg_reload_conf();"`（或 `systemctl reload postgresql`）。
   docker-compose.yml 已把容器网络固定为 172.28.0.0/24，这行规则永远有效；若该网段与服务器上其他 Docker 网络冲突，换一个子网并同步改 pg_hba。

5. **停掉旧后端**（服务器上若有裸机 uvicorn 占 8000，先停）。

6. **构建并启动**（首次构建约 5~10 分钟，大头是 torch CPU 版下载约 200MB）：
   ```bash
   docker compose up -d --build
   ```

7. **验证**：按「六、部署验证清单」逐项检查。

## 四、日常更新

```bash
cd ~/Saros-python
git pull
docker compose up -d --build   # 依赖层有缓存，未变时秒过；代码变化自动重建
docker compose logs -f backend # 看到「嵌入模型已加载」即完成
```

- backend/.env 与 backend/data 都在 gitignore 里，git pull 不会动它们。
- 修改了宿主 backend/.env 后：`docker compose up -d --force-recreate backend` 重启生效。
- 改 compose 端口/挂载等编排配置：重新执行 `docker compose up -d` 即可。

## 五、常见问题

- **backend 一直 unhealthy / 反复重启**：`docker compose logs backend`。常见原因：PG 连不上（ensure_user 报错）、backend/.env 没放、模型目录不存在。
- **PG 连不上**：容器访问宿主机自身 IP 时源 IP 是 172.28.0.x，确认「首次部署」第 4 步的 pg_hba 行已加并 reload；`docker exec saros-backend python -c "import socket; socket.create_connection(('100.109.98.117', 5432), 5)"` 可快速测连通。
- **ASR 转写报错**：容器出站被 SNAT 成宿主机 Tailscale IP，确认 ASR 机器放行了**Linux 服务器**的 Tailscale IP（若此前后端跑在 Mac 上，可能需要新增放行）。
- **写媒体/保存设置报 Permission denied**：容器内是 UID 1000 非 root，宿主文件属主需一致：`sudo chown -R $(id -u):$(id -g) backend/data backend/.env`（服务器用户非 1000 时用此命令一次性对齐；或改 compose 加 `user:`）。
- **问答流式输出卡住**：确认走 80 端口（nginx 已配 proxy_buffering off + 3600s 读超时）；直连 8000 不经过该配置，属预期。
- **构建报 torch 版本找不到**：CPU 索引版本更新时 pin 具体版本，改 backend/Dockerfile 对应行：`pip install "torch==2.7.1+cpu" --index-url https://download.pytorch.org/whl/cpu`。
- **构建时下载 torch/依赖很慢**：国内网络可换镜像源，如把 CPU 索引换成 `https://mirrors.aliyun.com/pytorch-wheels/cpu/`，pip 源换成清华/阿里镜像。
- **80 端口被占**：compose 里改一行 `- "8080:80"`。
- **启动后 10~30 秒无响应**：正常，嵌入模型预加载在 lifespan 里，healthcheck 已留 90s 起步期。
- **Mac 上构建 backend 镜像失败（找不到 darwin 的 torch wheel）**：正常现象，torch CPU 索引只有 Linux wheel；backend 镜像在服务器上构建，Mac 本地用 dev.sh。

## 六、部署验证清单

- [ ] `docker compose ps`：backend healthy、frontend running
- [ ] `docker compose logs backend`：看到「默认用户就绪」「嵌入模型已加载」
- [ ] 服务器本机 `curl http://127.0.0.1/api/health` 返回 ok
- [ ] 浏览器访问 `http://服务器IP/`：页面正常，刷新任意子路由不 404（history 回退生效）
- [ ] 问答流式输出流畅不卡（SSE 配置生效）
- [ ] 提一个 B 站视频任务：下载、音频切片（ffmpeg）、大纲出题全链路正常
- [ ] 视频详情页播放器可拖动进度（Range 透传生效）
- [ ] 知识库录入 + 语义查询正常（pgvector 链路）
- [ ] 设置页保存 → `docker compose restart backend` → 值仍在（.env 挂载写回链路）
- [ ] `docker compose restart backend`：中断任务被标记失败且可重试（恢复逻辑正常）

## 七、阶段三（Java 后端）切换

1. 新 Java 服务进 compose（如服务名 `java-backend`，指向同一 PG、挂载同一 backend/data）；
2. 改 `frontend/nginx.conf` 中 `proxy_pass http://backend:8000;` → `http://java-backend:8080;`（两处）；
3. `docker compose up -d --build frontend`：前端代码与浏览器书签零改动；
4. `docker compose stop backend`：Python 后端退场；数据仍在 PG 与 data 目录，可随时回退。
