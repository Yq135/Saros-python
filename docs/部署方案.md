# Saros 部署方案：前后端拆分 + 后端 Docker 化

> 2026-08-20 制定。目标：前端与后端拆开部署，后端容器化运行在 PG 所在的那台 Linux 服务器上；前端与数据库保持为阶段三（Java 后端）的复用资产。

## 1. 背景与目标

阶段二（Python 原型）已搭建完成，目前只有 `dev.sh` 的开发模式（FastAPI 8000 + Vite 5173）。改为生产式拆分部署：

- **后端**：Docker 容器化，运行在 PG 所在的那台本地 Linux 服务器
- **前端**：nginx 容器（与后端同一 docker-compose）托管静态文件 + 反代 `/api`，浏览器只访问 80 端口
- **数据库**：保持现状——Linux 服务器上的 PG 不进 Docker，阶段二/三共用、零迁移（ROADMAP §4.2 既定决策）
- **阶段三对齐**（ROADMAP §5.2）：Vue 3 前端不动，反向代理 `/api` 指向 Java 后端。届时只改 nginx 的 `proxy_pass` 目标，前端容器与浏览器入口零改动

代码经 GitHub 远程（origin: Yq135/Saros-python）分发，服务器 `git pull` 获取。

## 2. 部署架构

```
浏览器 ── :80 ──> [nginx 容器] 前端静态文件 + 反代 /api
                      │ proxy_pass http://backend:8000（docker 服务名）
                      ▼
               [backend 容器] FastAPI :8000（单实例，进程内任务队列，禁止 scale）
                      │
     挂载 ./backend/data:/app/data   （媒体/模型/cookie，与宿主机共用）
     挂载 ./backend/.env:/app/.env   （设置页写回即持久，见 §5「关键发现」）
                      │
     出站经宿主机 NAT ──> PG（宿主机自身，pg_hba 加一行放行容器网段）
                      └──> ASR（另一台 Tailscale 机器）
```

## 3. 关键事实（方案依据）

- lifespan 启动时连 PG、预加载 bge-small-zh-v1.5 嵌入模型（10~30s，期间不响应请求）、恢复中断任务、起进程内单 worker 队列 → **单实例**；`/api/health` 在 lifespan 后才响应 → healthcheck 要 `start_period`
- 系统级依赖 **ffmpeg**（asr.py 音频切片、视频合并）
- `backend/.env`（gitignore）实际值：PG_HOST=100.109.98.117（服务器自身 Tailscale IP）、ASR=100.100.61.45（另一台 Tailscale 机器）、EMBEDDING_MODEL 与 COOKIE_PATH 均为相对路径（基于 backend/，容器内 /app 下自然成立）→ **.env 内容零改动可用**
- `backend/data/` 432MB（gitignore）：媒体 + cookie + 嵌入模型，需 rsync 同步到服务器
- **关键发现**：settings_service.py:18 `ENV_FILE = BACKEND_DIR / ".env"`——设置页保存会**写回 .env**。若 compose 用 `env_file:` 注入，环境变量优先级高于 .env 文件（pydantic-settings），容器重启后设置页保存的值会被启动注入的旧值静默覆盖。→ **必须用单文件挂载 `./backend/.env:/app/.env`**（与裸机行为完全一致）。注意：首次 up 前 .env 必须存在，否则 Docker 会在该路径建目录
- 前端 `src/api.js` BASE 为相对 `/api` → **前端代码零改动**；vue-router 是 history 模式（nginx 需 `try_files` 回退）；SSE 流式接口（/qa/ask、/webpages）→ nginx 需 `proxy_buffering off` + 长 read timeout
- 现有 CORS 硬编码仅放行 localhost:5173（main.py:39）→ 改为可配置（nginx 同源反代下其实不触发，保留给 dev 直连与灵活性）
- yt-dlp==2026.7.4 被 pin（2026.7.4 起弃用 Python 3.10）→ 基础镜像锁定 **Python 3.10**
- 开发机 Mac 没有 Docker → 容器相关验证全部在服务器上做；Mac 侧只做代码改动 + pytest + dev.sh 回归
- Linux 网络细节：容器访问**宿主机自身 IP**（PG_HOST）时不做 SNAT，PG 看到的源 IP 是容器网段地址 → pg_hba 需加一行放行；compose 固定子网 172.28.0.0/24 使该行永久稳定

## 4. 文件改动清单

| 文件 | 动作 | 说明 |
|---|---|---|
| `backend/Dockerfile` | 新建 | python:3.10-slim + ffmpeg/tzdata；torch CPU 版单独装；非 root UID 1000；urllib 健康检查 |
| `backend/.dockerignore` | 新建 | 排除 .env、data/、tests/、缓存 |
| `frontend/Dockerfile` | 新建 | 多阶段：node:22-alpine 构建 → nginx:1.27-alpine 托管 |
| `frontend/.dockerignore` | 新建 | node_modules/、dist/、.git/ |
| `frontend/nginx.conf` | 新建 | history 回退 + /api 反代（SSE 关缓冲）+ /api/media Range 透传 |
| `docker-compose.yml` | 新建 | backend + frontend 两服务；固定子网 172.28.0.0/24；数据/.env 挂载 |
| `backend/app/config.py` | 修改 | 新增 `cors_origins` 设置项 + `cors_origin_list` 属性 |
| `backend/app/main.py` | 修改 | CORS 中间件改为读配置 |
| `backend/.env.example` | 修改 | 追加 CORS_ORIGINS 注释段 |
| `docs/部署说明.md` | 新建 | 服务器首次部署 + 日常更新 + FAQ + 验证清单 + 阶段三切换 |
| `README.md` | 修改 | 目录树加 compose 行；新增「Docker 部署」小节；配置表加 CORS_ORIGINS |

各文件内容要点：

- **backend/Dockerfile**：`FROM python:3.10-slim`；apt 装 `ffmpeg tzdata`（--no-install-recommends）；**torch 单独装 CPU 版**（`pip install torch --index-url https://download.pytorch.org/whl/cpu`）后再装 requirements（sentence-transformers 见 torch 已满足，不拉 CUDA 版；PyPI 默认 CUDA wheel 约 2.5GB，CPU 版整体镜像约 1.5~2GB）；分层先 COPY requirements.txt 再 COPY app（依赖层缓存）；`useradd -m -u 1000 saros` + USER saros；CMD 单 worker uvicorn（注释禁止 scale）；HEALTHCHECK 用 `python -c "import urllib.request; ..."`（不装 curl），`--start-period=90s` 覆盖模型加载期
- **frontend/nginx.conf**：`location / { try_files $uri $uri/ /index.html; }`；`location /api/ { proxy_pass http://backend:8000; }` + `proxy_http_version 1.1`、`Connection ""`、`proxy_buffering off`、`proxy_read_timeout 3600s`（SSE）；`location /api/media/` 加 `proxy_request_buffering off`（Range 透传 + 大文件流式）；gzip、`client_max_body_size 100m`；注释注明阶段三只改 proxy_pass 目标
- **docker-compose.yml**：`name: saros`；网络固定子网 172.28.0.0/24；backend 挂载 `.env`（单文件）+ `data`（目录）、`TZ=Asia/Shanghai`、`ports: "127.0.0.1:8000:8000"`（仅服务器本机看 /docs）、`restart: unless-stopped`、`stop_grace_period: 120s`、json-file 日志轮转 10m×3；frontend 挂 `80:80`、`depends_on: backend: condition: service_healthy`、wget 健康检查
- **CORS 改造**：config.py 新增 `cors_origins: str = "http://localhost:5173,http://127.0.0.1:5173"`（默认值与现状一致）+ `cors_origin_list` 解析属性；main.py 顶部加 `from app.config import settings`（无循环 import），中间件改为 `allow_origins=settings.cors_origin_list`

## 5. 关键决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 基础镜像 | `python:3.10-slim` | yt-dlp pin 约束；与 conda 开发环境对齐 |
| torch | CPU 版单独装（pytorch CPU 索引） | CUDA 默认 wheel 大 10 倍；装完再装 requirements 不冲突 |
| 模型/数据 | 挂载 `backend/data`，不进镜像 | 432MB 且持续增长；代码相对路径零改动；与阶段三 Java 共用 |
| .env | **单文件挂载**，不用 env_file | 设置页写回 .env，env_file 优先级更高会吞掉保存值 |
| PG 访问 | 保持 bridge 网络 + pg_hba 加一行 | 容器访问宿主机自身 IP 不 SNAT，源 IP 是 172.28.0.x；固定子网后一次配置永久有效。备选 host 网络模式放弃（失隔离、阶段三迁移要改） |
| 运行用户 | 非 root UID 1000 | 挂载卷不留 root 属主文件；8000 端口无需特权 |
| 单实例 | 注释禁止 scale，不配多副本 | 进程内任务队列是单 worker，多实例互相打架 |
| 日志 | stdout + json-file 轮转 | 不引入日志组件；TZ=Asia/Shanghai + tzdata |
| 镜像体积 | 约 1.5~2GB（拉取约 800MB~1GB） | 依赖缓存分层 + .dockerignore 挡 data；够用不优化 |

## 6. 实施步骤

### 阶段 A：代码改动（Mac 本地）

1. CORS 改造：config.py + main.py + .env.example
2. 新建 6 个 Docker 文件 + docs/部署说明.md + README 改动
3. Mac 侧回归（无 Docker，容器验证留服务器）：`cd backend && ~/anaconda3/envs/saros/bin/python -m pytest tests/ -v` 全绿；`./dev.sh` 冒烟（页面/问答流式正常，确认默认 CORS 无回归）
4. git add + commit + push（部署链路依赖 git 分发代码）

### 阶段 B：服务器首次部署（Linux，PG 所在机）

1. 前置检查：`docker compose version`、`tailscale status` 能看到 ASR 机器、80 端口空闲
2. `git clone`（或已有仓库 `git pull`）
3. `scp backend/.env`；`rsync backend/data/` 同步到服务器
4. pg_hba 加一行 `172.28.0.0/24` + reload
5. 停旧后端 → `docker compose up -d --build`（首次 5~10 分钟）
6. 按 §8 验证清单逐项验收

### 阶段 C：日常更新

`git pull && docker compose up -d --build`——依赖层缓存使未变依赖秒过。

## 7. 风险与注意

- torch CPU 索引随时间演进，若最新版不再支持 py3.10 → Dockerfile pin 具体版本（部署说明 FAQ 已写）
- 国内网络拉 download.pytorch.org 可能慢 → FAQ 提供镜像源替换方案
- ASR 若此前只放行 Mac 的 Tailscale IP → 需新增放行服务器 IP（部署说明已列）
- 服务器用户 UID 非 1000 → 一次性 `chown` 对齐（部署说明已列）
- Mac 上构建 backend 镜像会失败（CPU 索引无 darwin wheel），属预期，不是 bug

## 8. 部署验证清单（服务器）

- [ ] `docker compose ps`：backend healthy / frontend running
- [ ] `docker compose logs backend`：看到「默认用户就绪」「嵌入模型已加载」
- [ ] 服务器本机 `curl http://127.0.0.1/api/health` 返回 ok
- [ ] 浏览器访问服务器 80 端口：页面正常、刷新子路由不 404（history 回退）
- [ ] 问答流式输出流畅（SSE 配置生效）
- [ ] B 站视频任务全链路：下载 → ffmpeg 切片 → ASR/大纲 → 播放器拖动（Range 透传）
- [ ] 知识库录入 + 语义查询正常（pgvector 链路）
- [ ] 设置页保存 → `docker compose restart backend` → 值仍在（.env 挂载写回链路）
- [ ] `docker compose restart backend`：中断任务标记失败可重试
